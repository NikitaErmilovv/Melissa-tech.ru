# Почему «Операции» полные, а главная пустая

## Как устроена организация (multi-tenant)

У каждой студии свой `companyId` в БД. Пользователь владельца привязан к **своему** `companyId`.

## Главная (дашборд)

Считает только:

- заказы **этой** организации (`orders.companyId`);
- с заполненным **`postedAt`** («проведено в выручку»);
- графики «сегодня» / неделя — по **дате `postedAt`**, не `createdAt`.

Если заказы есть, но без `postedAt` (бокс / черновик / не нажали «В выручку»), на главной выручки **не будет**.

## Продажи

Показывает заказы организации, у которых **ещё не указаны расходники** (`materialsSet = false`). После ввода материалов заказ уходит из списка и попадает в зарплату.

## Клиенты в подсказках

Раньше список клиентов брался **из всей БД** (в т.ч. демо `companyId = 1`), поэтому подсказки были «чужими». В локальной ветке исправлено: фильтр по `tenantCompanyId`.

## Операции

Раньше `orders.list` тоже **не фильтровал** по организации — отсюда «куча» записей при пустой главной. Исправлено в `boot.js` на ветке.

## Демо-данные

Часть старых тестовых данных привязана к **`companyId = 1`** (DEMO). Новая организация (Владислав / Авто Блеск) имеет **другой id** — её кабинет изначально **пустой**, это не баг изоляции, а отсутствие своих заказов с `postedAt`.

## Что сделать, чтобы «увидеть жизнь» на главной

1. Создать заказ со статусом **выполнен** (`done`) — тогда `postedAt` проставится сразу, **или** в боксе нажать **«В выручку»**.
2. На **Продажах** ввести расходники (можно `0`), чтобы ушло в зарплату.
3. Либо (админ/миграция) скопировать демо-данные с `company_id=1` на id вашей студии — только осознанно, не на прод без бэкапа.

## Локальный тест (туннель + `LOCAL_PREVIEW=1`)

Главная считает **заказы с `postedAt`**. Для тестового кабинета «Автоблеск» при локальном preview:

- при входе **«Владелец»** и при открытии **Главной** подставляются демо-заказы/расходы за 7 дней (если проведённых заказов < 5);
- прайс копируется с демо-организации (`companyId=1`), если у студии свой каталог пустой.

Перезапустите локальный `node dist/boot.js` после обновления `boot.js` и обновите страницу.

Деплой правок `boot.js` на Timeweb — только после проверки на туннеле.
